# Forager v0.14.0

Forager v0.14.0 turns the project into a practical local autonomy meta-harness:
tmux-backed agents can be supervised through durable approvals, evidence,
recovery, closeout, and reviewed knowledge instead of terminal scrollback alone.

## Highlights

### Governed Offdesk operation

- Added durable task, approval, execution brief, runtime probe, recovery,
  closeout, decision receipt, and accepted-truth boundaries.
- Separated completed execution from accepted truth. Results remain pending
  until the evidence and follow-up state support an accepted receipt.
- Added provider-capacity handling, task-scoped tick, resumable background
  work, mutation snapshots, and fail-closed stale-state checks.
- Added Ondesk review, workstation, decision inbox, action envelope, runtime
  dispatch, artifact index, retention, and accepted-truth recovery surfaces.

### Telegram Remote Operator

- Added grounded free-form chat, project focus, read-only workspace tools, and
  a shared project registry.
- Added guarded plan preparation, approval, enqueue, task-scoped runtime,
  monitor, closeout, and closeout-verdict flows with durable receipts.
- Added exact live-session delivery for Codex and Claude. Ambiguous targets are
  rejected and clarified instead of selecting the first matching agent.
- Added prompt-bound waiting cards, confirmation expiry, durable inbound
  journals, a reply outbox, listener locking, health reporting, and an external
  watchdog.
- Added a bounded overnight autonomy window that remains inert until an
  operator confirms it.

### Adaptive Wiki and project continuity

- Added candidate, review, promotion, projection, correction, provenance, and
  usage records for reusable operating knowledge.
- Added project-scoped wiki planes, review proposals, distillation tools, and
  compact `.wiki-brief.md` projections with confidence and freshness signals.
- Added `forager go`, project registration and synchronization, project-aware
  status, and TUI project navigation.

### TUI and Web operator surfaces

- Fixed first-screen navigation, stale alternate-screen cells, profile config
  resolution, and tmux selection/scroll behavior.
- Moved preview capture and status polling away from the TUI input/render path.
- Added shared operator-state projections, semantic TUI summaries, and local
  Web routes for review, dashboard, work, decisions, graph, settings,
  portfolio, and knowledge.
- Added desktop and mobile Playwright coverage for 32 operator-surface
  scenarios.

### Release and operational hardening

- CI now covers Linux and macOS tests, Rust 1.88 MSRV, formatting, Clippy,
  Python script compilation, installer integrity, website audit/build, action
  bridge tests, and Playwright visual checks.
- Release builds publish Linux and macOS binaries for amd64 and arm64, the
  legacy `aoe` aliases, a platform-independent Telegram operator bundle,
  checksums, and a source-bound release provenance receipt.
- The install path verifies archive checksums before replacing a binary.

## Compatibility and operator notes

- `aoe` remains available as a legacy compatibility binary, but `forager` is
  the canonical command and storage namespace.
- Linux configuration defaults to `$XDG_CONFIG_HOME/forager` or
  `~/.config/forager`. macOS continues to use `~/.forager`.
- Existing AoE data remains discoverable. Run `forager doctor` before using
  `forager migrate aoe` to review migration conflicts.
- Operator-supplied Telegram runtime dispatch remains disabled by default.
  Curated `/run` templates and all mutation-capable paths retain explicit
  confirmation and receipt gates.
- New Forager-managed Claude sessions disable Claude's alternate screen so
  tmux scrollback, selection, and wheel behavior remain available. Existing
  standalone Claude sessions are not changed.

## Validation baseline

The release candidate is required to pass:

- `cargo fmt --all -- --check`
- `cargo clippy --locked --all-targets --all-features -- -D warnings`
- `cargo test --locked --all-targets --all-features` on Linux and macOS
- Rust 1.88 MSRV checks
- Python operational-script compilation and installer/provenance tests
- `npm audit --audit-level=high`, website build, action-bridge tests, and all
  Playwright operator-surface scenarios

The release asset `release-provenance.json` records the exact tag, source
commit, and SHA-256 digest of every published archive. The adjacent checksum
files remain the installation integrity boundary.
